# UI workflow live acceptance

Use this operator-run checklist against the exact deployed digest. Test only approved disposable resources. Record results privately with source/image/config identity, environment versions, plan/operation/object IDs, actor and observation timestamps, outcomes, issues, reviewer and date. Do not commit credentials, tokens, screenshots, response bodies, full manifests or private backend details.

Item IDs are stable: `PC` profile create, `PU` update, `PD` delete, `VC` dynamic PVC, `VE` expansion, `VS` legacy static pair, `VR` reservation, `VP` registration/PodDefaults, `NB` start, `NP` stop, `NR` resource edit, `NM` mount edit, `PR` Pod restart, `NC` Node cordon, `SY` storage edit, `SD` storage delete/reclaim, `UI` surfaces, `MR` refusals, `HY` hygiene.

## Evidence and preconditions

Inventory is a non-atomic observation. Preview means validation/dry-run; accepted means queued; succeeded means workflow-specific convergence passed. None proves future availability, application reachability or data recovery. `needs-review` is uncertain, not success or failure; inspect actual state. PVC creation may succeed while WaitForFirstConsumer leaves it Pending.

- [ ] **P1–P5** Pin/review the immutable image, configuration, protected namespaces and disposable namespace allowlist. Start all flags/controller confirmation false; run one replica/database writer. See [deployment](deployment.md).
- [ ] **B1–B4** Before writes/migration, take and isolate-restore a verified, encrypted off-node backup using [backup](backup.md).
- [ ] **D1–D4** Confirm the Profile/namespace, storage and Notebook are disposable, contain no valuable data and have informed owners. No system/Kubeflow namespace is in scope.
- [ ] **G1–G13** Enable one feature/grant pair at a time using [the capability matrix](deployment.md#6-apply-read-only-then-a-disposable-write-pilot). Test UI and direct-API denial with each gate off. Profile-delete ClusterRole can be narrowed by `resourceNames`; this does not constrain cascade. PodDefault base reads must work even with mutations off. Disabling flags neither revokes RBAC nor releases locks.
- [ ] **C1–C3** Independently verify the installed Notebook controller digest, stop annotation/culling behavior, child ownership and generated Pod/admission before setting `controllerContractConfirmed`. Dry-run alone is insufficient.
- [ ] **ID1–ID6** Verify owner identity/login/home-directory expectations externally. Creation requires email syntax but does no directory lookup. Update supports an unchanged legacy username owner; ownership transfer is unsupported.

## Workflow checks

Capture plan and operation IDs for every submitted workflow. Follow it to a terminal state and independently verify the actual object/application/storage outcome.

### Profiles

- [ ] **PC1–PC7** Create a Profile with a valid lowercase DNS-1123 label (maximum 63) and externally verified email owner. Reject uppercase, `_`/`.`, leading/trailing `-`, overlength and existing Profile/Namespace names. `.`/`_` suggestions are advisory. Review owner/quota preview, confirm once, then verify exact Profile owner and same-name owned namespace/annotation after Refresh.
- [ ] **PU1–PU11** Update one supported quota. Owner is read-only. Prefill comes from Profile quota spec, including zero values; unknown keys remain verbatim; existing supported keys cannot be omitted/emptied. Review only intended before/after changes. Reject owner changes, changed unmanaged keys and stale/missing `baseConfigDigest`; Profile replacement and later identity/RV changes require fresh review. A bare device key such as `nvidia.com/gpu` must produce its enforcement warning without migration to `requests.<device>`. Verify actual device enforcement through disposable admission/`status.used`, not declarations.
- [ ] **PD1–PD12** With the gate off, verify no control/API plan. On the disposable owned Profile, require reason, exact untrimmed name and separate plan confirmation. Preview describes cascade and affected classes. Background deletion of only the Profile delegates namespace cleanup; app never deletes Namespace/finalizers. Success requires original Profile and owned namespace absent; replacements/Terminating/read errors do not count. Namespace must be active and controlled by exact Profile UID with matching owner annotation; site must prevent cross-namespace/reparenting races. Unfinished cleanup is `needs-review` with Profile/namespace locks and child mutations refused. Verify retained PVs, snapshots and backend data separately: Delete can destroy data; Retain is not backup. Never use deletion to clear another incident. Check Operation/Audit evidence.

### Storage provisioning and management

See [storage configuration and constraints](storage.md) before these checks. Static uniqueness and unused checks are not atomic with other writers; coordinate admission and maintenance windows.

- [ ] **VC1–VC7** Create a typed PVC with an explicitly approved class and valid size/mode; unapproved classes and duplicate names refuse before mutation. Preview reclaim policy and WaitForFirstConsumer behavior. Verify creation and phase independently; Pending means created, not provisioned. Schedule an approved disposable consumer yourself to verify binding/capacity. Exceeding observed quota headroom refuses before mutation.
- [ ] **VE1–VE6** Expand only a bound, nonterminating, explicitly classified CSI claim with matching driver/claimRef and expansion-capable class. Refuse unbound/Lost/class-less/NFS targets and equal/smaller sizes. Preview only request growth. Success needs reported capacity >= requested without active resize conditions; independently verify mounted filesystem/backend/quota. No shrink or class/mode/mode-type change.
- [ ] **VS1–VS8** From an approved legacy NFS/CSI template, create a combined Retain PV+reserved PVC pair only on operator-prepared distinct storage. Browser cannot change fixed server/driver/handle/attributes. NFS input must be canonical relative strict descendant; CSI accepts no subpath and requires matching class provisioner. Refuse template class/mode mismatch and duplicate backend. Verify exact PV claimRef/bound claim and preview warning that no directory, permissions or allocation is performed. Site coordinates uniqueness beyond the app.
- [ ] **VR1–VR4** Reserve only an approved Available, unreserved, Retain, Filesystem PV without affinity/topology constraints and matching class/capacity/modes. Released/Bound/incompatible targets refuse. Verify only claimRef reservation + exact bound PVC; backend/spec is unchanged.
- [ ] **VP1–VP11** Configure approved registration templates and verified isolated classes. Create standalone NFS and BeeGFS PVs with template-owned spec; NFS accepts approved root/descendant, BeeGFS only a relative suffix and joined handle <=128 bytes. Refuse escape/traversal/encoding/duplicate/unapproved classes. PV remains unclaimed and Available; verify independently without publishing handles. Bind a new claim to exact compatible Available PV, with template-controlled request/modes independent of PV capacity and UID/RV protection. NFS UID/GID are nonzero decimals and only the two approved intent annotations; verify real permissions. Probe 52-byte new PodDefault names and cleanup of existing valid names up to 253.

  Test optional PodDefault off/on: no standalone control; correct namespace/claim, one volume/mount and independent selector. Existing name requires overwrite acknowledgement, diff and stale-identity refusal. Verify webhook/mount only on a new disposable opted-in Notebook Pod; existing Pods stay unchanged. PVC references from any Pod/Notebook including stopped block deletion before cleanup. Once unused, explicitly review all <=32 related PodDefaults plus PVC; shared/external warnings require acknowledgement and other PVCs remain untouched. Denied discovery/lists, malformed dependencies, new/changed references or >32 refuse. Controlled partial failures preserve actual receipts/PVC, never recreate PodDefaults or roll back; ambiguous outcomes retain `needs-review` locks without replay/finalizer removal.
- [ ] **SY1–SY6** Names open exact Resource Details; StorageClasses have no mutation. With gates off, Edit is unavailable/explained and API refuses. With gates/RBAC, fresh restricted YAML identifies kind/namespace/name/UID/RV and exposes only console labels plus PV reclaim or PVC request. Hidden backend/annotations/other labels/status/owners/finalizers stay unchanged. Reject identity/unsupported fields/duplicates/aliases/multi-doc/no-op and stale editor. Verify guarded Available-PV Retain/Delete edit warning and upward-only gated PVC resize. Close/Escape restores focus; late responses cannot populate another target; opening performs no write.
- [ ] **SD1–SD5 (including SD3a reclaim)** With gates off, Delete is unavailable/API refused. With gates/RBAC, require reason, exact name, data-loss acknowledgement and plan. Refuse Pod/Notebook-referenced PVC, bound/reserved/referenced/non-Available PV, read/list errors, protected/out-of-scope resources. Delete only approved unused storage, record UID/operation and verify disappearance/backends according to reclaim policy. Stale identity, drift, timeouts or finalizers retain `needs-review` locks without replay/force.

  Default unused Retain-bound PVC deletion leaves PV Released and sends no patch. Separately test per-plan reclaim with `pvReclaim`, grant, isolation and acknowledgement: preview data exposure; Delete-policy PV never patched; missing patch RBAC refuses before PVC deletion; success yields same PV Available/no claimRef, PVC still deleted. On standalone Released Retain PV with old claim gone, test **Reclaim PV** with exact name/reason/exposure acknowledgement. Reject replacements, referencing or pending matching claims (including beta annotation), stale UID/RV, Delete policy/wrong phase and absent isolation. Verify only claimRef removal + available receipt. Any post-delete/reclaim uncertainty preserves PVC/PV outcome and locks, without recreate/retry. Reuse means data exposure, not wipe.

### Notebooks, Pods and Nodes

- [ ] **NB1–NB5** With writes and confirmed controller contract, start the disposable Notebook. Preview exact target/state/warnings. Start removes stop and stale idle-activity annotations, but does not disable culling or continuously refresh idle activity. Verify expected owned Pod Ready and app reachable independently; understand site idle policy may stop it again.
- [ ] **NP1–NP4** Stop sets the stop annotation with timestamp, without direct Pod delete/eviction. Expect possible loss of kernels/processes/writable layers/unsaved files; PV is not memory checkpoint. Verify stopped state and controller-owned workload disappearance/termination. Unfinished outcome is `needs-review`, never replayed.
- [ ] **NR1–NR7** Select exact namespace/Notebook/named container. Only approved images and bounded GPU presets/counts are accepted. Blank optional image/resource fields preserve values; GPU zero clears placement; removed preset configuration refuses rather than silently drops. Preview only intended fields. Edit stops first; explicit restart option restores a previously running Notebook, otherwise it stays stopped. Reject resulting quota/LimitRange violations and verify unrelated containers/volumes/fields unchanged.
- [ ] **NM1–NM6** Unchecked mount editing preserves mounts; checked with no editable rows requests removal subject to protected paths. Refuse protected workspace/configured paths, duplicate names/paths, unsafe/nonabsolute paths, subPath/subPathExpr, missing or cross-namespace claims and non-PVC-volume replacement. Unrelated volumes remain. Verify intended same-namespace claim and observed mounts after workload return.
- [ ] **PR1–PR6** Enable restart grant/flag and contract, preferably namespace-scoped. Only Running Pods owned by StatefulSet controlled by running Notebook in allowed namespace pass; unmanaged/static/mirror/terminating/stopped-parent/unhealthy-Node targets refuse. Eviction is PDB-aware with UID/RV preconditions, never forced deletion. Success requires old UID absent and distinct correctly owned replacement Ready at desired revision. PDB refusal deletes nothing and permits fresh plan; ambiguous interruption is `needs-review` without replay.
- [ ] **NC1–NC4** With Node grant/flag and admission review, require reason; Force is needed for control-plane/NotReady/repeated-state requests. Preview exact `spec.unschedulable` delta. Cordon does not evict/drain. Concurrent change refuses; verify final state and uncordon after test.

## UI and evidence hygiene

- [ ] **UI1–UI15** Exercise drawers via Close/scrim/Escape, focus restoration and Enter: only separate plan confirmation submits. Profile has one Summary with metadata/declared quotas/scoped links/actions; namespace summaries omit empty groups without claiming live emptiness. Namespace links scope namespaced pages and `?namespace=`; cluster pages remain unscoped. Clear filters removes search/resource/namespace scope and pagination; Back/Forward/refresh restore correct scope. Search all loaded rows before 50-row pages; History is bounded, not export.

  Ensure no UI/plan/history reveals credentials, tokens, kubeconfig/DB paths, environment values, full manifests or arbitrary PV backend details; approved template/path review is redacted in evidence. Notebook table lists Notebook CRs only; Resource Details identifies exact kind/namespace/name; Manage Notebook preselects exact target/container where known, preserves blank fields/mounts and clears edits when target changes. Gate explanations are visible and API-enforced. Test 390/1280px bounded table scrolling/layout, right-aligned Manage Notebook, Profiles ownership panel/New buttons and Overview Workspace Health composition. Refresh updates `ObservedAt`; failed fetch shows stale warning; navigation within freshness avoids new read. Notifications expand/collapse, deduplicate, prioritize errors/newest, expire info/success after 10s and never acknowledge warnings.
- [ ] **UI9** Node Scoped view shows exact-node observed Running Pods across namespaces, with matching filter chips, cleared unrelated filters, working zero matches/pagination/Back/Forward/Clear.
- [ ] **MR1–MR19** Exercise the refusal matrix: invalid/duplicate Profile names; omitted/changed/empty quota sets and owner/stale-digest changes; unapproved class; invalid expansion target/size; template mismatch/path escape/duplicate backend; invalid PV reservation; out-of-scope/protected Notebook action; unapproved image/GPU; invalid protected/duplicate/cross-namespace mount; disabled writes/workflow gate or wrong typed confirmation; expired/stale plan; duplicate idempotent submit; unauthenticated/non-admin/CSRF/forged identity request. Each refusal occurs before mutation, leaves no partial target and allows a corrected plan. Correct refusals pass.
- [ ] **HY1–HY8** Keep private status/duration/ID evidence without HAR/cookies/bodies/tokens. Verify Operation/Audit actor label, target, action, result, reason and stages; legacy rows use generic label. After pilot, disable flags and revoke exact optional RBAC separately, then verify read-only. Make an operator cleanup plan for disposable leftovers/backend data. Resolve every `needs-review` against real state; never edit lock rows. Record all results including refusals.
