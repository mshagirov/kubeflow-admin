PROFILE MANAGEMENT

Manage a profile

Resource limits for one workspace. The owner of an existing Profile is read-only: the installed Profile controller cannot transfer it.

A new Profile name is also its namespace name: lowercase letters, digits and interior hyphens, at most 63 characters, starting and ending with a letter or digit. It must not match an existing Profile or namespace.

This console never looks up a directory. Type the exact address registered with your identity provider; it is sent exactly as entered, including case.

Selecting a Profile loads its observed owner, quota and configuration precondition. The owner and the precondition are submitted unchanged; only the quota values are editable. Scopes and plugins are preserved by the server and are not editable here.

Owner transfer is unsupported by the installed Profile controller, so the current owner is read-only. The exact observed owner is submitted unchanged; only quotas can be changed.

Resource quota

Optional for a new Profile. For a quota update, every existing quota key must be supplied with its current value: clearing a key omits it and the server rejects the removal. Observed ResourceQuota hard/used details are not a substitute for the current Profile quota configuration.

DESTRUCTIVE ACTION

Delete a profile

Deletion removes the Profile and the namespace it owns. The namespace cleanup deletes the notebooks, pods and volume claims inside it, and it cannot skip namespaced objects: everything in the namespace goes with it, including objects the Profile does not own.

Back up anything you still need first. A volume claim with a Delete reclaim policy lets the storage controller delete the backing volume, which can be irreversible. A Retain reclaim policy is not protection: the backend lifecycle or a later operator delete can still remove the volume. A namespaced VolumeSnapshot is deleted with its namespace, and the snapshot content behind it follows its own Delete or Retain policy.

This console never wipes backend data itself and never removes a finalizer to force a deletion. An unresolved finalizer leaves the cleanup unfinished for an operator, and the operation is only successful once the Profile and its namespace are both absent.

The confirmation must match the profile name exactly, including case. It is sent exactly as typed and is never trimmed.
